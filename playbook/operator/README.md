A thin interactive layer over the playbook for the lab's own engagements —
the owner's and the lab's agents', on lab projects and client projects. It
exists because a playbook engagement runs weeks to months across many
sessions, and the corpus is a reference, not an experience: nobody should
be assigned fourteen chapters, and no session should reconstruct "where
were we" from memory.

**What it is:** a router (`START.md`), an intake interview
(`interview.md`), a routing doctrine (`routing.md`), and an append-only
engagement ledger (`ledger-format.md`). The chapters stay the only
normative content; this kit only navigates them and records what happened.
Delivery layer, never a fork: no chapter text is ever duplicated or
rewritten conversationally here.

**How an engagement starts:**

1. Create the engagement home — a private folder or repo **next to the
   client's code**, never inside the playbook repo (client data and the
   playbook never mix; see `ledger-format.md` for the layout).
2. Open an agent session there and point it at this kit:
   *"Read `<playbook path>/playbook/operator/START.md` and follow it."*
3. Answer the interview. Every later session starts with "hello" and a
   one-paragraph summary of exactly where the engagement stands.

**Audience boundary (permanent):** this kit serves the lab. Outsiders get
wikiskills-lab, which shares the patterns but no files. When an engagement
reaches a focus that fits wikiskills' five-step shape, the operator hands
off to it as a tool and records the handoff (ch. 07 §10 vendor recipe).

# Pattern Index

- [formula-strings-score-zero](wiki/patterns/formula-strings-score-zero.md): Writing Excel formulas via openpyxl (`=SUMIFS(...)`, `=IF(...)`, nested IF chains) scores 0 because openpyxl stores only formula text with no cached result, so a grader reading values sees `None`/a string — always compute in Python and write the literal value, even when the user asks for "a formula", "a macro/VBA" or "Power Query" (57558 and 263-1 scored 1.000 doing exactly this; 50916 has now lost 4 runs writing formula text).
- [openpyxl-save-wipes-cached-formula-values](wiki/patterns/openpyxl-save-wipes-cached-formula-values.md): `load_workbook()` + `wb.save()` drops the cached `<v>` of EVERY pre-existing formula in the file — including totals rows (`=SUM(H3:H6)`), helper columns (`=D3+F3`, `=G2*H2`) and cells you never touched — so they all read `None` for the grader; open a second handle with `data_only=True` and write those cached numbers back as literals over every formula in the graded sheet (48080, 50916, 247-24, 36097, 370-43 all lost runs this way).
- [compute-then-write-literal-values](wiki/patterns/compute-then-write-literal-values.md): Every 1.000 run parsed the workbook in Python, computed the answer in Python, wrote literal values (copying source style), then re-loaded the saved file with `data_only=True` to verify — this is the reliable action sequence for spreadsheet tasks.
- [preserve-prefilled-examples-in-answer-range](wiki/patterns/preserve-prefilled-examples-in-answer-range.md): Init files often pre-fill part of the answer range as worked examples; clearing/rewriting/reordering that range scores 0 — fill only the blank cells, but "preserve" means preserve the VALUE: if a pre-filled cell holds a formula you must literalise its cached result, because leaving the formula alone blanks it on save (48080 has now failed 3× doing the literal-minded thing).
- [validate-rule-against-worked-examples](wiki/patterns/validate-rule-against-worked-examples.md): Derive the rule, then prove it reproduces every prompt example and pre-filled cell before writing — and if one example does NOT reproduce (36097: H3 gave 4000 vs the given 5000), that is a stop-and-re-derive signal, never a "discrepancy" to ship past; the test must also *discriminate* between candidate rules (6239).
- [confirm-filter-predicates-match-real-values](wiki/patterns/confirm-filter-predicates-match-real-values.md): Delete/filter/match rules coded from the prompt's wording silently match 0 rows (247-24 iter4: `company == 'Motorcycle'` deleted nothing) or far too many (iter3: `'Cycle' in company`) because the real column values were never enumerated — print `sorted(set(...))` of the key column first and assert the predicate's hit count is non-zero and plausible.
- [inspect-full-used-range-and-locate-provided-examples](wiki/patterns/inspect-full-used-range-and-locate-provided-examples.md): When the prompt says "I've attached an example / before-and-after sheet", it exists somewhere in the used range — 370-43 dumped only A1:T20 of a sheet whose dimensions were A1:T2483, never found the reference block, and scored 0; scan every sheet's full `ws.dimensions` for non-empty islands outside the main table before deciding what the answer looks like.
- [threshold-tables-vs-payout-tables](wiki/patterns/threshold-tables-vs-payout-tables.md): A numeric block next to a lookup grid is often the *band edges* (per-bucket thresholds), not values to add; 6239 read the goal×variance threshold table as "base incentive" and summed it with the payout grid, mis-banding every employee — before coding, state "this block is X indexed by Y" for each table and check the numbers against the ranges quoted in the prompt.
- [honor-explicit-ordering-and-output-range](wiki/patterns/honor-explicit-ordering-and-output-range.md): "Keep the original order / do not sort within the group" is violated by adding an unrequested tiebreaker to the sort key (22-47 sorted every group by REF) — use a stable sort keyed on the group only, assert each ordering clause on the final list, and write only the columns named as output (it also clobbered pre-filled column F).
- [row-edits-break-relative-formulas](wiki/patterns/row-edits-break-relative-formulas.md): Deleting/inserting rows moves formula strings like `=G2*H2` to new rows unchanged (stale references) and read-all-then-rewrite loses styles too — this happens with `delete_rows()/insert_rows()` as well; literalise every formula column *before* moving rows (247-24 has now failed 4×, 370-43 once).
- [dynamic-header-lookup-not-hardcoded-columns](wiki/patterns/dynamic-header-lookup-not-hardcoded-columns.md): Tasks where a column/sheet position "changes daily" fail with hardcoded letters; scan the header row for the label to get `cell.column_letter` at runtime, then copy values *and* style — this earned 1.000 twice (408-39, iters 1 and 4).
- [verify-answer-range-values-not-formulas](wiki/patterns/verify-answer-range-values-not-formulas.md): "Verification" that echoes back the formula string just written proves nothing; re-open with `data_only=True` and assert against independently computed expected values — a `None` in ANY graded cell (including ones you deliberately left untouched, and totals rows outside your write range) is a hard failure, never to be downgraded to a weaker `data_only=False` check (3413, 48080 ×2 did exactly that).
- [apply-requested-formatting-explicitly](wiki/patterns/apply-requested-formatting-explicitly.md): When the instruction names concrete formatting ("all borders for C2:C6, Courier New 9pt", "preserve the formatting of column I"), it is part of the grade; set/copy the style on every named cell and verify the style attributes after reload — 39903 scored 1.0 doing this.

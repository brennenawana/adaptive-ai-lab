# Pattern Index

## Failure Patterns
- [write-values-not-formulas](wiki/patterns/write-values-not-formulas.md): Target cells left holding formula STRINGS (SUMPRODUCT/AVERAGEIFS/INDEX-SMALL/SUMIFS/nested IF/INDEX-MATCH) via openpyxl; no cached result exists, so a value-reading grader sees None — 0.0 every time (iters 1,2, 263-1 in iter 4, 50916 in iters 5, 7 and **8, where it printed the whole expected answer table and then wrote 18 INDEX/MATCH strings instead**; 10747 regressed 1.000→0.000 in iter 7 this way and recovered to 1.000 in iter 8 by writing the literal). FIX: compute in Python, write literal values, verify `not str(v).startswith('=')` — but literals are NECESSARY, NOT SUFFICIENT (56786 wrote 197 correct-looking literals and still scored 0.0).
- [test-negative-examples-too](wiki/patterns/test-negative-examples-too.md): A match/classification rule was scored only on rows expected to MATCH (192-22 iter 8 tested 13 hand-picked positives), so an over-broad rule — "any single word of a multi-word keyword" — passed and flipped every blank-oracle row; 1.000 (iter 2) → 0.000 (iter 8). FIX: score every candidate over ALL oracle rows (a blank oracle cell is a negative example), print tp/fp/fn/tn and require fp==fn==0; when exactly one row resists an otherwise perfect rule, prefer "source typo" over widening the rule.
- [macro-vba-dynamic-requests](wiki/patterns/macro-vba-dynamic-requests.md): Prompts saying "I need a macro / VBA / Power Query / make this dynamic / where have I gone wrong with my formula / help me copy it across" trick the agent into shipping code or live formulas (263-1, 50916 ×4, 10747 in iter 7 → 0.0), but the graded artifact is always the saved workbook read by VALUE (10747 in iters 5 and 8, 472-15 ×2, 82-30, 55060, 3413, 42354 all scored 1.0 by writing the literal and putting the formula/VBA in prose only).
- [contradicting-oracle-cells](wiki/patterns/contradicting-oracle-cells.md): Files ship with pre-filled worked-example cells (H3=5000, H3=1660/H4=2753, sample column I, E4:E8, D2:D5 of 42354, G3/G4 of 3413); in iteration 8 "reproduce the oracle then fill ONLY the blanks" separated 3/3 winners from 5/5 losers — every loser wrote into an already-filled cell (36097 destroyed H3=5000 for the SIXTH time, 194-19 overwrote the sample ranks, 50916 the cached D12/F12/H12, 192-22 twenty `'None'` strings). FIX: `assert ws[coord].value is None` before every write; the oracle also DEFINES unstated rules (3413's G4=27 revealed the "sum the whole department" fallback).
- [prompt-example-as-oracle](wiki/patterns/prompt-example-as-oracle.md): The prompt itself states the answer for one case ("'2 to 5' should count as 4 days", "Z-07-…:9 is excluded", "AVERAGE(B24:B69)", "based on I3 and J3, placed in K6"); winners encode it as a `(input → expected)` test table and assert before writing, losers paraphrase it away (10747 retargeted I3/J3→I6/J6; 56786 ignored the quoted range; 6239 accepted a NON-DISCRIMINATING example). FIX: transcribe every example sentence into asserts, use the exact cell refs named, and check the example can actually distinguish your rival rules.
- [formula-cell-cached-value-loss](wiki/patterns/formula-cell-cached-value-loss.md): `data_only=True` values are a SNAPSHOT of the last Excel save — they vanish when you re-save, they do not shift when you insert/delete rows, and overwriting a formula cell throws its value away (247-24 iter5 "Formula in I48 has no cached value" ×40; 50916 clobbered D12/F12/H12='French'/'Science'/'Social Studies' in iters 5, 7 AND 8). The snapshot often already CONTAINS the answer (10747: `K3 = -10600`). FIX: dump every cached value into a Python dict keyed by ORIGINAL coordinate before any write or structural edit, then write literals.
- [aggregate-match-is-not-verification](wiki/patterns/aggregate-match-is-not-verification.md): A candidate rule was accepted because its SUM equalled a stale cached `=SUM()` total while an author-typed cell disagreed (36097 iter 6), and 6239 (iter 7) accepted "J+P" because the prompt's only example gives 0.03 under BOTH candidate rules. One equation cannot validate N unknowns, and an example that every candidate passes proves nothing. FIX: rank rules by PER-CELL agreement with author-typed literals; require the test to DISCRIMINATE; if no candidate reproduces every oracle cell, keep enumerating readings.
- [fabricated-rule-overfitting](wiki/patterns/fabricated-rule-overfitting.md): When a derived rule missed the oracle or the spec left a case uncovered, the agent invented unmotivated arithmetic (`+cost/4`, `2*(profit-cost+bv)`, `max(0,…)`, an invented `+` delimiter producing `++`), remapped a named value to a lookalike ('Motorcycle' → 'Mehommod Cycle'), or relaxed a multi-word keyword to single words — 36097 in iters 2-6, 170-13 in iter 7, 247-24 and 192-22 in iter 8. FIX: every branch/separator/synonym must quote a clause or the example; enumerate alternative READINGS of existing terms instead of adding new ones; a one-row mismatch is usually a data typo, not a rule change.
- [hardcoded-range-truncation](wiki/patterns/hardcoded-range-truncation.md): Agent inspects/writes only a hardcoded window (`range(1,15)`, `range(4,25)` on a 515-row sheet, `header_rows={1,8,14,21}`, `final_sorted[:9]`), never deriving bounds from the data, then verifies with the same window so truncation is invisible (32438, 10452, 194-19, 370-43, 22-47 ×2, 56786 ×2). FIX: print dimensions first, derive the last data row from the data, never slice the result to fit an assumed output range, verify with an independent count.
- [plan-pipeline-before-mutating](wiki/patterns/plan-pipeline-before-mutating.md): Interleaving exploration with live-sheet mutation led 247-24 (iter 6) to restart mid-mutation and end with NO output file → 0.0; 6239 (iter 7) burned its whole budget dumping the two lookup tables cell-by-cell and no write/save step ever appears. FIX: read the sheet into a list of dicts in one pass, write the ordered step list down before any mutation, save an output file EARLY with the best-known answer and refine it, and print summaries not per-cell logs.
- [zero-match-filter-check](wiki/patterns/zero-match-filter-check.md): A filter on a value the user named matches 0 rows (type mismatch, whitespace, wrong spelling); the requirement is then either silently skipped with a vacuous re-check, or — worse — REMAPPED to the nearest-looking value (247-24 iter 8 deleted 5 'Mehommod Cycle' rows "assuming this is 'Motorcycle'"). FIX: print `sorted({repr(v) for v in col})` and `type(v)` BEFORE filtering; only normalize case/whitespace/substrings of the SAME token; a genuinely absent value makes the requirement a verified no-op, never a fuzzy match.
- [replicate-completed-example-block](wiki/patterns/replicate-completed-example-block.md): When the user says "I completed the first meet as a sample" / "I filled in a couple of examples" / "an example is provided", that block defines the rule; 194-19 has now failed FOUR times with four different mappings (latest: assigning J/K/L/M by row-occurrence index instead of by Tab-number position), 56786 never found the examples, 170-13 wiped Sheet3 before reading it. FIX: locate the example, state the mapping in one sentence, regenerate the completed rows and assert a 100% diff match before touching any new row.
- [time-value-vs-text-string](wiki/patterns/time-value-vs-text-string.md): For "format column J to show only the time" the agent wrote `strftime('%I:%M:%S %p')` STRINGS — twice (32438 in iters 3 and 5); its closing check only asserted "not a formula", which text passes. FIX: write a `datetime.time`/`datetime` value and set `cell.number_format='h:mm:ss AM/PM'`, and assert the TYPE (`not isinstance(v,str)`), not just the absence of `=`.
- [excel-date-serial-vs-datetime](wiki/patterns/excel-date-serial-vs-datetime.md): Date cells often come back as raw serial ints (44392) instead of datetimes, so year/date-range bucketing silently fails or raises TypeError; 47766 scored 1.0 by converting with `datetime(1899,12,30)+timedelta(days=n)` and printing the serial for each year boundary. FIX: probe `type()` of every date column and normalize both sides to datetime before any comparison.
- [cell-value-type-mismatch](wiki/patterns/cell-value-type-mismatch.md): Comparisons fail because openpyxl returns ints (`5551234`) while the code tests `== '5551234'`, exact string equality misses case/whitespace (`'8CPARK  /03-27-2021'` vs `'8CPark'`, `'PORT MACQUARIE '`), and an empty cell (`None`) is not the same as a cell holding the string `'None'` (192-22). FIX: print `repr(v), type(v).__name__`/`cell.data_type` during inspection and normalize both sides (`int()` / `str().strip().upper()`, substring `in`) — this fix turned 58484 from 0.0 to 1.0 and won 472-15 twice.
- [openpyxl-row-insert-delete](wiki/patterns/openpyxl-row-insert-delete.md): `insert_rows`/`delete_rows` shift cells but do NOT retarget formulas, do NOT shift your parallel `data_only` workbook, and invalidate saved indices (247-24 failed in iters 2,3, scored 1.0 in iter 4, then 0.0 in iters 5, 6 and 8). FIX: materialize all formula cells to values FIRST, re-scan for target rows after every structural change, insert blank rows LAST, then assert the final row count — and never delete a row unless the filter that selected it is exactly the one the user named.
- [legacy-array-formula-cse](wiki/patterns/legacy-array-formula-cse.md): INDEX/SMALL/IF "filter" formulas require Ctrl+Shift+Enter array entry which openpyxl cannot mark, so they yield #VALUE!/blank (10452 iter 1). FIX: emit the literal filtered list of values instead — exactly what turned 10452 into a 1.0 in iter 7.
- [openpyxl-formula-fill-down](wiki/patterns/openpyxl-formula-fill-down.md): Assigning the same formula string to a column does not shift relative refs (every row kept `A4`), and `from openpyxl.formula import Translator` raises ImportError; generating refs by string-building instead often over-anchors them (50916 emitted `$B$12` in rows 13 and 14 — the very copy-across bug it was asked to fix). FIX: `from openpyxl.formula.translate import Translator`, or preferably write per-row computed values.
- [save-before-write-ordering](wiki/patterns/save-before-write-ordering.md): Workbook was saved BEFORE the output cells were written, leaving a stale/empty output file. FIX: mutate all cells first, save last, then reload the saved file and assert target cells hold expected values.
- [ambiguous-multi-rule-spec](wiki/patterns/ambiguous-multi-rule-spec.md): Long instructions with conflicting rules or multi-axis lookup grids led to guessing — 22-47 failed in iters 1, 5 and 6 by promoting the trailing tiebreaker ("sort only column H") to the primary sort key, and 6239 failed three times on a 3-axis rule (Goal × Variance × Metric2). FIX: enumerate every stated rule, ensure every named input appears in AND is used by your function, weight interpretations by how much text the user spent on them, and hand-derive the expected first rows.

## Success Patterns
- [verify-against-reference-sheet](wiki/patterns/verify-against-reference-sheet.md): Every scoring task across iters 1-8 computed results in Python, wrote literal values, then re-opened the saved file with `data_only=True` and diffed against an oracle/hand-derived expectation (82-30 printed `Match: False`, changed its extraction order and re-ran until True; 42354 and 3413 printed `✓ Oracle verified` on every pre-filled row before filling the blanks); every failure ran a verification that only re-checked its own choices (192-22 tested 13 positives, 50916 printed formulas back, 36097 narrated past a `MISMATCH`). FIX/DO: verification must compare against something you did NOT produce, must be able to print ✗, and any ✗ is blocking.
- [preserve-formatting-requirements](wiki/patterns/preserve-formatting-requirements.md): Tasks bundle formatting clauses (borders, bold, wrap text, "no bordering on column G", "preserve column I formatting") with the computation; 39903 (1.0 three times) and 58484 scored 1.0 by applying each clause to the exact stated range and verifying after reload. Number formats need a real typed value to render; clearing a border means `cell.border = Border()`; `shutil.copy(init, output)` then editing the copy (42354, 1.0) preserves everything you were not asked to touch.
